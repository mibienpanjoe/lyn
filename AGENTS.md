# Repository Guidelines

## Project Structure & Module Organization

Lyn has a Svelte/Tauri implementation; `README.md` is the entry point. Read `docs/project_overview.md`, then `01_requirements_prd.md` through `09_local_speech_distribution_decision.md`. Preserve requirement, invariant, and error IDs across documents.

Svelte 5/TypeScript UI lives under `src/`; the Tauri/Rust core lives under `src-tauri/`. Window IPC is gated by `src-tauri/capabilities/` (`main` Library vs `capture` popup) referencing permission sets in `src-tauri/permissions/` plus `build.rs` `AppManifest::commands` allowlists—never `core:default` path/image escape hatches. Separately delivered local context integrations live under `integrations/`: VS Code reports v1 focus heartbeats plus versioned v2 invoke frames (workspace folders as correlation hints; `surface` editor vs focused terminal; window identity is assigned by Rust), the Kitty watcher reports exact pane focus plus child process identity and a no-UI kitten invokes capture from that pane, and the generic shell bootstrap starts the bounded `lyn-context` helper (Lyn refreshes that helper next to the app on launch so users do not build a second binary). Native Messaging uses the same running binary via `~/.local/share/lyn/bin/lyn-browser-host`; the companion reports v1 tab heartbeats plus a v2 invoke from the focused tab (`lyn.capture`). Editor, Cursor, and Kitty invoke with `Ctrl+Alt+Shift+L`. The browser companion suggests `Alt+Shift+L` because Chromium rejects `Ctrl+Alt+*` suggested keys; Firefox MV3 loads `background.scripts` (not a service worker). The Settings global shortcut is a distinct grab (default `Control+Shift+Space`) and cannot reuse the integration combination. All provider traffic uses private Rust-owned sockets and excludes commands, output, environment values, titles, and client-supplied paths. Linux editor and browser sockets also check the connecting peer uid, bound the read, and ignore a replayed v2 invoke generation. Localhost mapping requires one same-user process cwd after skipping `docker-proxy`; IPv4/IPv6 sockets of the same directory are one source, and multiple distinct cwds stay unresolved. 1-click integration status checks and installations are managed under `src-tauri/src/integrations/` and exposed via `commands::integrations` to the Library window. Ordered SQLite migrations live under `src-tauri/migrations/` and must remain immutable after release. Keep presentation and IPC clients in `src/`; storage, capture-session state, context detection, media, and OS integration belong in Rust. Capture-session transitions live in `src-tauri/src/capture/session.rs`; provider observations and their ephemeral registry live under `src-tauri/src/context/`; command gateways live under `src-tauri/src/commands/`, parameterized context/capture persistence stays under `src-tauri/src/storage/`, and platform-specific shortcut/focus/audio/popup-layout adapters stay behind `src-tauri/src/platform/` ports. Recoverable media staging is in `src-tauri/src/media/staging.rs`; PNG/WAV normalization stays under `src-tauri/src/media/`, and startup reconciliation reads durable media references through `src-tauri/src/storage/media_assets.rs`. Staged previews resolve through the read-only `lyn-media://` protocol by opaque ID; the capture/library CSP allows that scheme (and the Windows `lyn-media.localhost` form) on `img-src`/`media-src` only. None of these boundaries may expose raw filesystem paths to the UI.

On Linux, GNOME Terminal may inherit `KITTY_WINDOW_ID` from its launcher. Its own `GNOME_TERMINAL_SCREEN` marker keeps the shell helper enabled, while Rust rejects generic shell observations for actual Kitty windows. A new shell helper binds only to the actual foreground window, never Lyn's remembered window. Once bound, it keeps its process/window heartbeat alive in the background; background reports must not replace the remembered foreground window. Multiple sessions in one terminal window still require explicit selection. Editor integration status reports the current embedded extension version as installed, but file presence alone does not prove a live connection or successful capture.

The developer-only native GNOME prototype is under `integrations/gnome/prototype/`. It uses GTK3/VTE to relate terminal widgets to native windows and PTYs, without terminal stream access. Its version-0 diagnostic datagrams are not accepted by the production brokers; v1 stream queries are tested against both a Python fixture and the real Rust broker. The latter uses a bounded same-user control socket compiled only under cfg(test), never an application command or authentication bypass. Cargo's current test artifact determines the harness executable. The module is neither packaged nor installed by Lyn. Its harness uses Xvfb, a private D-Bus and isolated XDG directories; never point its actions at the user's terminal server. On Pop!_OS use `gnome-terminal.real` to address the already-created fixture server instead of the per-launch wrapper. Keep ordinary GNOME support limitations until native window/PTY attestation, capture wiring and installed-package acceptance are delivered.

The isolated runner gives each fixture a private process group and a 60-second lifetime; on timeout it kills that owned group and reaps its leader. Keep that bound and the nested-process timeout test. This is not a general audit of arbitrary daemonized descendants or the native module's production resource lifetime.

The prototype defers its initial stream connection to one GTK main-context idle callback, owning a copied endpoint or discovery-runtime path until callback removal; do not spend handshake/output deadlines while GTK initialization cannot dispatch I/O. The channel lifecycle owns its separate address copy until explicit stop, at most one stream and one pending retry, with 100 ms–2 s connection backoff. Start means configured, not admitted; every reconnect clears framing/generation state and performs a fresh handshake. Discovery mode revalidates the current publication before each connection attempt, never on behalf of a replayed query. Never retry a query or capture automatically. Explicit stop cancels watches/retry and frees the address. Preserve the 300 ms pre-loop-delay regression in both modes and unchanged 500/120 ms protocol limits. Its private GTK fixture executable is not a real GNOME admission proof; retain the separate system-server/Rust harness and never weaken peer executable validation to accommodate that fixture. The native suite checks 100 start/stop cycles per mode without FD growth or a later connection, and real GNOME admission/capture when the fixed-endpoint broker starts late and restarts with a new generation; desktop discovery/crash/installed acceptance remain separate.

The native GNOME v1 contract is owned by `docs/gnome_native_protocol.md` and `context/gnome_protocol.rs`, with its C codec in `integrations/gnome/wire.c`. Its fixed 112-byte codecs have shared valid/refused wire vectors; those and single-use invocation validation are not a running integration. The future dedicated broker must attest peer/server/window/PTY/process identities before promoting decoded metadata to a source; ordinary editor/browser payloads still cannot supply native IDs. Reject topology changes at or after invocation, including equal microsecond timestamps and A→B→A; opening Lyn and losing OS focus alone does not invalidate an unchanged tab. No PTY FD or stream access is permitted. Keep the 120 ms reply refusal bound distinct from measured input/context latency targets.

Native peer admission lives in `context/gnome_peer.rs`: kernel credentials, allowlisted root-owned executable inode, proc identity and a polled pidfd. Do not replace unavailable pidfd support/permissions with a numeric-PID heuristic. Its tests require Linux pidfd support and Python3 for an isolated connecting-process fixture; restricted sandboxes may require running these tests outside the sandbox. Peer admission alone does not attest the window/PTY or register a context source.

`context/gnome_channel.rs` owns the native stream handshake and one-at-a-time exchange. Deadlines are absolute Linux monotonic times, not per-read timeouts; reject future invocation timestamps and never reset the 120 ms budget on partial input. Transport/correlation errors close/drop the socket; only a correlated explicit unresolved reply may keep it for a fresh request. Never receive PTY FDs: the metadata channel rejects ancillary data. Channel tests use real socket pairs with test-only fixture-peer authentication; they do not establish a running broker or GNOME kernel/window/PTY attestation.

`context/gnome_listener.rs` owns only the private native endpoint and cancellable idle accept. Never unlink occupied endpoints; shutdown may remove only the recorded socket inode. Preserve private directory/socket permissions, final-component symlink refusal and the explicit pending-connection backlog. A subprocess regression kills only a pidfd-pinned private listener owner and requires its abandoned socket to remain unchanged and a new bind to refuse; that is safety evidence, not crash recovery. Accepted streams are not authenticated sources: they must pass the native peer/channel boundary and later window/PTY attestation.

The fresh-instance publication/discovery contract in `docs/gnome_native_protocol.md` was approved on 2026-10-19. `context/gnome_endpoint.rs` now owns its Rust publication lease: stable private flock file, fresh private instance, atomic bounded record, pinned descriptors/inodes and nonrecursive owned cleanup, with limits of 64 instance names and 4096 inspected entries. Never unlink the lock or abandoned sockets. Explicit unlock follows cleanup, including failure paths, because a concurrent spawn can briefly inherit the open file description before CLOEXEC. `NativeBroker::start_published` publishes from the ready admission worker and drops listener before lease, including spawn failure; retained broker Arc owners must not delay explicit shutdown. `integrations/gnome/native_discovery.c` is the bounded C address reader, tested by the canonical native runners through Python/ctypes; it checks private metadata without final-component symlinks, retains directory/record descriptors, rechecks identity and never connects, scans or deletes. A stale socket may yield an address hint, not liveness or admission. `lyn_native_start_discovered` connects that reader to the existing lifecycle. The developer prototype opts in through `LYN_GNOME_TEST_DISCOVERY` instead of `LYN_GNOME_TEST_STREAM`; supplying both refuses channel configuration. The same-user two-endpoint C transport fixture proves fresh handshake/generation and no query replay, not production peer admission. Linux app startup now uses publication; fixed-endpoint start is test-only. The private real desktop fixture uses discovery and reuses the actual C reader for controller readiness. Its default/concurrent/late-app/clean-restart paths have passed with painted Library screenshots inspected. App-crash and installed recovery remain unverified, and no module is installed or distributed yet.

`context/gnome_broker.rs` composes admission and exact-server routing on one worker, with at most eight admitted server PIDs and one pending handshake. No registry/session mutex may span channel I/O; a busy channel or reconnect refuses rather than queues. Reconnection invalidates the previous generation. `query_window` derives/rechecks ownership through `platform/x11_owner.rs` and fences the current connection generation after OS checks; raw-PID exchange stays private. XRes 1.2, local Unix transport and one exact server-advertised client range/PID are required; never fall back to `_NET_WM_PID`. X11 wire I/O has an absolute 100 ms deadline; trusted Xauthority filesystem lookup is separate. This window evidence still needs PTY/process attestation. Linux startup now attempts the private broker; module discovery/installation and desktop acceptance remain pending. Broker unit fixtures authenticate only the current test executable under cfg(test); the real GNOME harness calls NativeBroker::start and preserves the production system-server peer policy. The Rust runtime harness pins fixture child cleanup with pidfd after validating its private-server parent/TTY; preserve this rather than signalling a remembered numeric PID. Its Xvfb stop/resume test must target only the pidfd-pinned member of its private fixture group/session.

`context/gnome_pty.rs` cross-checks the admitted server's master through bounded `fdinfo` metadata and descriptor-target stat/readlink, never opening the terminal stream. `query_window_pty` confirms native topology after all kernel observations under the original invocation deadline, then fences owner/channel generation again. Inodes/PTY numbers can recycle and are not lifetime identities. Support direct devpts and the root-managed legacy `/dev/ptmx` sibling-pts route; reject different namespaces/roots, unknown routes and duplicate masters. This observation alone does not attest a process group or cwd; it must not be registered as an automatic capture source.

`context/gnome_process.rs` checks all live foreground-group members, not just a PGID-named process or the same-uid subset. It requires matching controlling TTY/tpgid/session, same-user ancestry to the admitted server, matching roots/namespaces and one canonical cwd; snapshots retain pidfds and require final liveness/deadline checks after native/XRes exchanges. `ProcessInvocation::now` must be minted in Rust at invocation before popup/owner/socket work, freezing BOOTTIME for process starttime separately from MONOTONIC transport deadlines. Never reconstruct the historical suspend offset later. Known system proxy inodes are refused, not an exhaustive custom-remote-client classification.

`context/gnome_capture.rs` prepares an attested native source/Git context outside session/registry locks. Its lease retains the original window, generation, candidate and kernel lifetime pins; fresh selection/save queries must match all original evidence, not merely a source ID or cwd string. Later continuity queries have distinct bounded deadlines, not a reset of the initial invocation. Commit the single native registry entry only after its session ticket is accepted; bind it to the owner session and release it on successful text/image/audio save, cancellation or popup close. Native entries do not expire by heartbeat TTL and never enter generic automatic snapshots. A remembered window is not fresh native invocation proof; GNOME without native evidence stays unresolved, never helper-exact. The isolated backend harness covers native preparation → save_once → SQLite → Library gateway with synthetic notes. The separate real desktop fixture's coverage and remaining reinforced-run checks are owned by `docs/gnome_native_protocol.md`; neither harness proves installed desktop acceptance. Ordinary GNOME support limitations remain until module activation, popup/focus and package acceptance pass.

## Coding Style & Naming Conventions

Write concise Markdown with descriptive headings and relative links. Keep numbered filenames stable. Never present proposed designs as implemented or verified.

Use `rustfmt` and Prettier. Use `snake_case` for Rust modules/functions, `PascalCase` for Rust types and Svelte components, and kebab-case for TypeScript utility files. Import individual outline icons from `@lucide/svelte/icons/*`; keep visible labels on capture actions and match icon stroke to adjacent text. Preserve typed Tauri IPC; the frontend must not access SQLite or arbitrary filesystem paths.

## Testing Guidelines

The editor extension 0.1.3 contributes a `terminal.integrated.commandsToSkipShell` default containing `lyn.capture`; it never writes user settings. Explicit user/workspace routing overrides remain authoritative. Validate terminal invocation without a manually added skip-shell entry, including a terminal cwd different from the editor workspace.

The editor broker uses blocking Unix `accept` rather than polling idle connections. Accepted messages retain their uid/size/read-deadline checks; only accept errors back off. Measure shortcut-to-input and shortcut-to-context separately on the current packaged binary before claiming latency budgets.

The X11 editor classifier accepts both legacy `Code` and the installed VS Code namespaced `com.microsoft.VSCode` WM_CLASS, by exact case-insensitive match. Do not broaden this to substring matching; confirm the actual class when validating a new editor package.

Linux text, image, and audio saves share native shell source revalidation against the registered process uid/inode and current project directory, not only the heartbeat TTL. A closed or changed source must return `CONTEXT_SOURCE_STALE` without modifying the active draft or finalizing staged media. Tests cover each capture kind; packaged runtime acceptance is a separate check.

Every behavior change must include tests at its owning boundary. Prioritize Rust domain tests, IPC serialization/negative tests, media recovery tests, and keyboard/accessibility UI tests. Follow the verification matrices in documents 05–07. Record commands once a runner exists.

## Commit & Pull Request Guidelines

History is small; prefer concise Conventional Commit-style messages such as `docs: clarify capture invariants`, `feat: add text capture`, or `test: cover duplicate saves`. Keep commits atomic.

Pull requests should explain scope/rationale, link requirements or issues, list verification, and call out deferred work. Include screenshots or recordings for UI changes and identify contract, invariant, dependency, permission, or data-model changes.

## Security & Product Boundaries

Lyn is local-first. Core capture must not depend on accounts, cloud APIs, or remote AI. Treat clipboard data, paths, window titles, and media as untrusted. Never log capture content or commit secrets. Project directories must enter through the Rust-owned native picker; expose only expiring one-use tokens and safe labels to the frontend, never raw paths or generic filesystem permissions. Bind automatic context to the pre-popup foreground window; never use a global last-reported session or expose terminal, editor, or agent content. Context correction must preserve the draft. Preserve “save first, enrich afterward” and user-authored metadata precedence.

The Rust capture-session service owns the single active session and save idempotency. Commands must not derive session state from popup mount/unmount events or perform persistence outside the service's serialized `save_once` boundary. Text blankness checks must not rewrite the body; durable text and its FTS projection are accepted only after the SQLite transaction commits.

`CaptureSession.contextRevision` orders context snapshots within one session only. Register popup listeners before bootstrap; reject older context events/responses without losing newer media or the draft. Linux automatic resolution uses a bounded worker and Rust-only single-use query tickets. Text/image/audio save preflight snapshots the private context epoch, releases the session mutex for source/context lookup, then refuses any intervening context/session change before entering `save_once`. Actual capture persistence and media finalization remain inside that serialized boundary. Do not hold session/registry locks across native provider I/O. These prerequisites do not establish production native GNOME capture wiring; see `docs/06_api_specification.md` for the receiving contract.

Update this guide in the same change whenever repository state, commands, structure, contracts, or contributor workflows change. Breaking API, invariant, data-model, security, or platform changes require matching guidance updates.
